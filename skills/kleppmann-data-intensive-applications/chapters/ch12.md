# 第 12 章：The Future of Data Systems

**来源**：OCR Markdown 第 10056—11254 行，含作者的观点性结论与伦理讨论。图 12-1 未取得。技术预测、法律与产品例子是成书时的历史陈述；现实使用需核验现状。

## 集成多种数据系统

没有一种数据产品适配所有读写模式。先画全组织的数据流：每项事实从哪里首次写入、谁决定顺序、哪些索引/缓存/模型/仓库是派生结果、怎样重建。统一写入顺序再通过 CDC 或事件日志维护派生视图，可避免应用双写的并发逆序和部分失败。异步派生提高故障隔离，但默认有时效延迟；对读己之写等要求需显式等待日志位点、提供同步读路径或其他协调。分区、跨地域、多服务与离线客户端会破坏全局总序；对有因果依赖的操作记录来源事件、版本或共同分区，外部通知一类不可撤回副作用尤其要谨慎。

批处理可以历史重算，流处理可以快速追新。重算让旧新视图并行、灰度切换和回退成为可能。Lambda 架构双套逻辑与输出合并成本很高；统一引擎需能重放历史、按事件时间开窗、恢复失败输出。数据系统“拆包”可理解为把数据库内部索引与物化视图维护扩展为跨产品的数据流；读侧联邦查询与写侧日志集成解决不同问题。只在单一产品无法满足需求时承担多组件运维成本。

## 把读写路径放在一张图上

派生索引/缓存/视图是写路径预计算与读路径即时计算的交界。过少预计算使读取昂贵，过多则使写入和存储膨胀。按访问频率、更新频率、时效目标选择边界。离线客户端可以保存本地副本并通过变更订阅追赶；初始化快照后用可恢复位点接续，断线重连不能漏消息。将读请求也视为事件有助于记录“用户决策前看到了什么”，但带来额外存储和隐私成本。对复杂多分区读取优先评估现成数据库的能力。

## 端到端正确性

数据库事务、TCP 去重或流处理的“恰好一次”只覆盖各自边界。用户提交请求后响应丢失可能手动重试，整个业务链仍会重复扣款。给业务操作生成**端到端 request ID**，从客户端传到权威存储，在同一原子事务内以唯一约束记录该 ID 与结果，再让下游按 ID 幂等处理。仅在应用代码中先查再写，会受到并发隔离漏洞影响。

严格唯一、库存硬约束等冲突操作必须路由到同一决策点或协同达成共识。多分区操作可先原子记录单个权威请求，再确定性派生各分区指令，以 request ID 去重；这能保持某些业务完整性，却不保证所有视图立即同步。作者区分**及时性**（多久看到新结果）与**完整性**（不丢、不重、不自相矛盾）：前者的违例可等待修复，后者常需显式对账修复。部分业务允许先接受后补偿，是否可接受由补偿成本、不可逆后果和业务规则决定；不能把“事后道歉”用于硬性约束或未经授权的财务风险。

## 信任但验证

硬件、网络、数据库和应用代码都可能罕见出错。为权威事件、派生视图和备份建立端到端校验：定期重算并对账记录数、金额与哈希，验证恢复演练能成功；保留能说明为什么发生某次变化的来源链。不可变事件与确定性派生便于审计、复现和纠错，但也增加隐私数据长期保存风险。

## 人的影响

作者的结语明确要求把数据系统对人的影响纳入设计。预测模型会放大历史偏见、代理变量歧视和反馈环；高影响自动决策需要可追溯、可申诉、人工复核与误判修复。追踪数据收集应有明确用途、真实选择权、最小留存与安全删除；法律现状和具体要求另行核验。技术“可采集”不等于应采集。

## 设计评审清单

1. 列权威事实、派生视图、写入顺序、分区与因果依赖。
2. 说明每条读路径的时效承诺、重放/重建流程和迁移回退点。
3. 对每项约束判断须同步拒绝，还是可补偿；记录业务后果。
4. 追踪端到端 request ID，模拟响应丢失、重试、旧主复活和下游重复消费。
5. 做端到端对账、备份恢复与数据删除演练。
6. 对涉及人的模型与追踪审查偏见、误判申诉、用途和留存。
