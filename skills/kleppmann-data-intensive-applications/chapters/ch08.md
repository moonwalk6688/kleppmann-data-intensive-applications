## 部分故障与不可判定的超时

单机程序常可观察为正常或崩溃；分布式系统可以某些节点和链路正常、另一些故障。请求无响应时，发送者无法仅凭超时区分请求丢失、远端停机、远端已处理但响应丢失、排队延迟或进程暂停。**超时是怀疑，不是故障证明**。重试可能重复执行，故需要幂等/去重；故障转移可能把仍活着的旧节点与新节点同时推到工作状态。短超时快但误判多，长超时慢但更稳；接近容量上限时队列延迟增大，误判和转移负载可造成级联故障。用实际延迟分布、抖动与过载场景选阈值，并注入断网、单向链路、延迟、丢包和部分节点失联测试。

网络排队可发生在交换机、接收端 CPU、虚拟机调度和发送端 TCP 流控；TCP 重传隐藏了丢包，却无法隐藏延迟。分组交换适合突发流量和高利用率，固定资源预留可给更强时延边界但成本高。互联网服务通常不能假设硬实时上界。

## 时钟的三种用途

**墙上时间**用于日期、日志和业务事件时间；可能因 NTP 调整、漂移、闰秒、虚拟化或设备人为设置而跳变，不能直接用于测时。**单调时钟**用于同一节点内计算超时与耗时，不应跨机器比较绝对值。**逻辑时钟/版本向量**表示事件因果顺序，不表示真实日期。跨节点 LWW 用墙上时间选“最新”可能把因果上较晚的写丢掉，精确到微秒的显示值也不代表微秒级准确度。若系统依赖时钟同步，监控偏移和误差边界，超阈值节点隔离。书中 TrueTime 把时间表示为 [earliest, latest] 区间，通过等待不确定区间结束保障事务时间顺序；不能把普通 NTP 时间戳当作同等保证。

## 进程暂停、租约与 fencing

GC、虚拟机迁移/挂起、操作系统调度、磁盘 I/O、换页或 SIGSTOP 都可能在任意指令间暂停进程。持租约节点暂停期间租约过期，其他节点接任；旧节点醒来后即使自认仍有租约，也可能写入并破坏资源。检查租约后紧接着执行操作仍有检查与使用之间的暂停窗口。**fencing token** 在每次发放租约时严格递增，客户端携 token 写资源；资源端记住最高 token 并拒绝更小 token。关键是资源端执行检查，客户端自查不足以防旧节点。若资源不支持 token，必须设计等效的拒旧机制并验证。

## 由多数决定，但仍需声明模型

单节点自认是 leader 不足以证明其他节点同意；需要多数或合适法定人数形成唯一决策。书中通常假定节点会故障但诚实；若节点任意作假则是 Byzantine 模型，协议成本显著不同，普通数据中心常用身份认证、输入校验、校验和等保护，不能把普通共识协议当作抗恶意节点方案。

系统模型按时间可分同步、部分同步、异步；按节点可分 crash-stop、crash-recovery 和 Byzantine。现实服务多以“部分同步 + 故障后恢复”近似，但稳定存储也可能损坏。评价算法时分清**安全性**（某次错误发生后无法撤销，如重复 fencing token）与**活性**（满足条件后最终完成）。安全性应在允许故障下始终保持；活性通常需要多数节点存活、网络最终恢复等附加条件。理论证明依赖模型，仍需故障注入和恢复演练。

## 可执行故障审查

1. 为每个远程操作标出超时后的“未知结果”，并定义查询结果、幂等重试或人工核对机制。
2. 测试丢请求、丢响应、单向网络、慢节点、长 GC/VM 暂停与时钟回拨。
3. 对选主、分布式锁和租约核对多数决策与资源端 fencing，模拟旧主复活。
4. 分开使用墙上、单调和逻辑时钟；监测时钟误差，避免用本地时间判断因果。
5. 把所需安全性、活性及其前提写成可验证条款，再做故障注入，而非只观察正常运行吞吐。
