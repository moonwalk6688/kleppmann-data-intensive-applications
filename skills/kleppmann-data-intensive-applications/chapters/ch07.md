## 事务提供什么保证

事务把多个读写组成逻辑单元：失败时撤销已做的写，成功时给出约定的持久性和隔离性。ACID 的 **A** 是中途故障可整体回滚，不是并发意义上的原子操作；**C** 是应用定义并维持的不变量，数据库只可检查其中部分约束；**I** 要落到具体隔离级别，不能凭“ACID”字样判断；**D** 需要磁盘、复制、备份共同降低风险，没有绝对不丢。单对象原子写、compare-and-set 或所谓“轻量事务”不等于跨多个对象的事务。外部邮件等副作用不会因数据库回滚而自动撤销。

多对象事务适合维护外键、反规范化副本、二级索引、邮件与未读计数等关联。重试要区分暂时性与永久性错误；提交确认丢失时“可能已成功”，应以幂等键/去重处理。过载时盲目重试会放大故障，需有限次数与退避。数据库之外副作用应延后或用可靠协调设计。

## 按异常而非名称选择隔离

| 异常 | 发生方式 | 常见保护 |
| --- | --- | --- |
| 脏读 | 读到另一事务未提交、可能回滚的写 | read committed 及更强 |
| 脏写 | 覆盖另一事务尚未提交的写 | 写锁；read committed 及更强 |
| 读偏斜/不可重复读 | 一次事务的不同读取看到不同时点 | 一致快照 |
| 丢失更新 | 两个客户端读旧值、各自修改写回，后者覆盖前者 | 原子更新、显式锁、可靠 CAS 或自动冲突检测 |
| 写偏斜 | 两个事务读同一前提，写不同对象后共同破坏不变量 | 可串行化、可锁定的共同约束对象或专门约束 |
| 幻读影响写入 | 查询“目前不存在”，并发插入改变谓词结果 | 谓词/索引范围保护或可串行化 |

Read committed 只保证不读未提交、不覆盖未提交写；它允许一次事务的多次读看到不同已提交状态。快照隔离让事务在同一一致时点读取，常用 MVCC 保留多个版本，读写彼此通常不阻塞；适合备份、长分析与完整性检查。但快照隔离不自动阻止写偏斜，某些实现甚至不自动阻止丢失更新。书中 PostgreSQL、MySQL、Oracle 等比较是当时版本；“repeatable read”“serializable” 标签在不同产品不等价，不能代替实际异常测试。

丢失更新优先用数据库原子操作（如计数器直接加一），复杂读改写可用 SELECT FOR UPDATE、可靠的条件更新或让数据库检测冲突并回滚重试。比较并设置的 WHERE 若在旧快照上判断，也可能不安全，必须核验实现。多主/无主复制的并发写需要版本合并，单主锁不一定可跨副本生效。

## 写偏斜：检查后写入的陷阱

书中的值班医生例子：Alice 和 Bob 都读到“有两人值班”，分别改自己的记录为不值班；每个事务只写不同的行，快照隔离都可提交，结果无人值班。会议室预约“无冲突才插入”、用户名唯一“未被占用才注册”、余额充足“才消费”、棋子位置“不存在才移动”也是同型问题。唯一约束能直接解决用户名例子；跨行不变量或时间范围重叠通常需可串行化或专门机制。若 SELECT 没返回行，FOR UPDATE 无行可锁；可构造公共锁对象（materialize conflict），但复杂且易错，应视为最后方案。

## 三种可串行化实现

**实际串行执行**把短事务装进预先提交的过程，在单线程顺序执行；避免锁协调，但受单核/内存和跨分区协调限制。适合快速、单分区且写负载可控的操作，不宜让人类交互或慢 I/O 留在事务内。

**两阶段锁 2PL**让读持共享锁、写持排他锁，持有到提交；可防写偏斜，但读写互相等待、死锁需回滚重试，争用导致尾延迟高。谓词锁能保护尚不存在的“幻影”行，实际常用更粗的索引范围锁，可能阻塞更多操作。2PL 是并发控制，**与两阶段提交 2PC 不同**。

**可串行化快照隔离 SSI**先让事务在快照上继续，追踪其读取是否被并发写破坏；提交时发现危险依赖则回滚重试。读者与写者不必互相阻塞，适合争用低且读写事务短的场景；争用高会提高回滚率，长读写事务尤其容易被取消。长只读查询可在一致快照上运行。书中对 SSI 性能的判断要结合实际工作负载验证。

## 实施检查

1. 写出关键业务不变量：唯一性、非负余额、至少一人值班、无重叠预约、多个记录同步。
2. 为每条不变量画两事务交错序列，区分脏读、丢失更新、写偏斜和幻读。
3. 选数据库实际支持的约束、原子操作或隔离级别，并用并发压测复现或排除异常。
4. 把事务范围缩短，监控锁等待、死锁、SSI 回滚、尾延迟和重试量。
5. 对提交超时、外部副作用、部分失败设计去重或补偿；明确跨分区/跨系统的保证。
